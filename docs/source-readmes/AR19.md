# AR-19 — OpenAPI v1 & HTTP Endpoint Contract Pack

Baseline HTTP contract for Portal Tattoo.

## Contract decisions

- Functional base path: `/api/v1`.
- Public routes are under `/public/*`.
- Administrative routes are under `/admin/*`.
- Admin endpoints use OIDC and explicit capability metadata.
- Mutable aggregate endpoints use optimistic concurrency through `If-Match` where applicable.
- Retry-prone/create operations support `Idempotency-Key`.
- Errors use `application/problem+json`.
- Public product DTOs expose canonical specifications, not unreviewed claims.
- Price history is observational and append-only.
- Editorial supports NEWS, BLOG, EVENT, TECHNICAL_ARTICLE and NOTICE.
- AI administration exposes provider metadata/configuration but never API secrets.
- OpenAI, Anthropic and DeepSeek are represented as configurable AI Hub providers.

## Health endpoints

`/livez` and `/readyz` remain operational endpoints outside `/api/v1` and are intentionally not mixed into the functional API contract.

## Client generation

The OpenAPI document is intended to be the source for `@portal-tattoo/api-client`. Generated clients must not be edited manually.
